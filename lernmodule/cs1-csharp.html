    01

    Was ist ein Programm?

    Du weißt, was ein Programm ist und wie aus einer Idee Schritt für Schritt Anweisungen werden.

    Ein Computer ist unfassbar schnell und unfassbar dumm. Er macht exakt, was dasteht. Nicht das, was du gemeint hast. Programmieren heißt deshalb: eine Aufgabe so genau in Schritte zerlegen, dass selbst eine Maschine ohne Fantasie sie richtig erledigt.

    Diese Schritte schreibst du als Quelltext in einer Programmiersprache auf, zum Beispiel C#. Der Quelltext ist für Menschen lesbar. Daraus entsteht später ein Programm, das der Computer ausführt.

    Eine genaue Schrittfolge zur Lösung einer Aufgabe heißt Algorithmus. Das Wort klingt nach Mathe-Olymp. Gemeint ist aber nur ein sehr gründliches Rezept.

    Idee → Algorithmus (Schritte) → Quelltext (C#) → Programm → Ausführung EVA-Prinzip: Eingabe → Verarbeitung → Ausgabe Tastatur, Rechnen, Bildschirm, Datei, Sensor Prüfen, Sortieren Datei, Drucker
    Fast jedes Programm folgt dem EVA-Prinzip: Eingabe, Verarbeitung, Ausgabe. Die CPU versteht nur Maschinensprache (Nullen und Einsen). Menschen schreiben in einer Hochsprache wie C#.
    VORGEMACHT
    Ein Mini-Programm, an dem du alle drei EVA-Teile siehst:
    Console.WriteLine("Wie viele Ports hat der Switch?");
int ports = int.Parse(Console.ReadLine()!);
int frei = ports - 2;
Console.WriteLine("Freie Ports: " + frei);
    1. Eingabe: Das Programm fragt und liest die Antwort von der Tastatur.
    2. Verarbeitung: Es rechnet 24 − 2, weil zwei Ports für den Uplink reserviert sind.
    3. Ausgabe: Das Ergebnis erscheint im Konsolenfenster.
    4. Jeder Schritt steht in einer eigenen Zeile. Der Computer arbeitet sie von oben nach unten ab, ohne zu fragen, ob das sinnvoll ist.

    Hochsprache und Maschinensprache

    Die CPU kennt nur sehr einfache Befehle als Bitmuster, etwa „lade Wert“, „addiere“, „springe“. Das ist Maschinensprache. Kein Mensch will darin eine Gerätedatenbank schreiben. Darum gibt es Hochsprachen wie C#, Python oder Java. Sie sind lesbarer und müssen vor oder während der Ausführung übersetzt werden. Wie genau, klärt Kapitel 2.

    Ein Algorithmus aus dem Alltag

    „Drucker einrichten“ als Schrittfolge: Treiber herunterladen, Treiber installieren, Drucker anschließen, Testseite drucken. Vertauschst du zwei Schritte, wird es spannend. Genauso ist es im Code: Die Reihenfolge ist Teil der Lösung.

    Syntax und Semantik

    Die Syntax ist die Rechtschreibung einer Sprache: Wo steht das Semikolon, welche Klammer gehört wohin. Die Semantik ist die Bedeutung: Was passiert, wenn die Zeile läuft. Ein Programm kann syntaktisch perfekt sein und trotzdem Unsinn tun. Der Computer merkt das nicht. Du hoffentlich schon.

    Wo dir Programme als Systemintegrator begegnen

    Skripte, die Benutzer anlegen. Tools, die Logdateien durchsuchen. Monitoring, das bei vollem Speicher Alarm schlägt. Du musst kein Softwareentwickler werden. Aber wer Code lesen kann, muss nicht jedes Mal hoffen, dass das Skript aus dem Forum schon passen wird.

    EVA IN ZEITLUPEKlicke dich Zeile für Zeile durch das Programm.
    Typische Fallen: „Der Computer weiß doch, was ich meine.“ Nein. Er weiß nur, was dasteht. Und HTML ist eine Auszeichnungssprache, keine Programmiersprache: Es beschreibt, wie etwas aussieht, aber es rechnet und entscheidet nichts.

    Compiler, Interpreter und .NET

    Du kannst Compiler und Interpreter unterscheiden und kennst den Weg deines C#-Programms bis zur CPU.

    Die CPU versteht nur Maschinensprache. Dein Quelltext muss also übersetzt werden. Dafür gibt es zwei Grundideen.

    Ein Compiler übersetzt das ganze Programm, bevor es startet. Findet er einen Fehler, startet gar nichts. Er ist der Kollege, der den kompletten Bericht liest, bevor er unterschreibt.

    Ein Interpreter liest das Programm während der Ausführung Anweisung für Anweisung und führt sie sofort aus. Ein Fehler in Zeile 50 fällt erst auf, wenn Zeile 50 dran ist. Bis dahin lief alles prima. Vielleicht sogar beim Kunden.

    CompilerInterpreter
    Wann wird übersetzt?vorher, alles auf einmalwährend der Ausführung, Schritt für Schritt
    Syntaxfehlervor dem Start, nichts läufterst, wenn die Zeile dran ist
    Ergebnisausführbare Dateikeine eigene Datei, Quelltext + Interpreter nötig
    Tempo beim Ausführenmeist schnellermeist langsamer
    Typische SprachenC, C++, Go, RustPython, PowerShell, Bash, JavaScript (klassisch)
    Compiler: erst alles übersetzen, dann starten. Interpreter: Zeile lesen, ausführen, nächste Zeile. C# nutzt beides nacheinander: Der C#-Compiler erzeugt Zwischencode (IL), und beim Start übersetzt der JIT-Compiler der .NET-Laufzeit ihn in Maschinencode.
    VORGEMACHT
    Was passiert, wenn in Zeile 3 ein Semikolon fehlt?
    Console.WriteLine("Backup startet");
Console.WriteLine("Kopiere Dateien");
Console.WriteLine("Fertig")
    1. Der C#-Compiler liest das ganze Programm, bevor irgendetwas läuft.
    2. In Zeile 3 fehlt das Semikolon. Er meldet CS1002: ; erwartet.
    3. Es entsteht kein Programm. Die Konsole zeigt gar nichts, auch nicht die ersten beiden Zeilen.
    4. Ein Interpreter hätte „Backup startet“ und „Kopiere Dateien“ noch ausgegeben und wäre erst in Zeile 3 gestolpert.

    Der Weg eines C#-Programms

    Program.cs → C#-Compiler (Roslyn) → .dll mit IL-Code ↓ beim Start CPU ← Maschinencode ← JIT-Compiler in der CLR (.NET-Laufzeit)

    IL (Intermediate Language) ist ein Zwischencode, der auf jeder Plattform mit .NET läuft. Die CLR (Common Language Runtime) ist die Laufzeitumgebung: Sie lädt das Programm, verwaltet den Speicher und räumt hinter dir auf. Der JIT-Compiler (Just in Time) übersetzt den IL-Code erst beim Ausführen in Maschinencode für genau diese CPU.

    C#, .NET und das SDK

    C# ist die Sprache. .NET ist die Plattform darunter: Laufzeit plus riesige Bibliothek fertiger Bausteine wie Console. Das SDK (Software Development Kit) brauchst du zum Entwickeln, es enthält den Compiler. Zum reinen Ausführen reicht die Runtime.

    Und welche Variante ist besser?

    Keine. Kompilierte Programme sind meist schneller und melden Tippfehler früh. Interpretierte Skripte änderst du einfach und startest sie sofort neu, ideal für schnelle Admin-Aufgaben. Darum schreibst du PowerShell-Skripte und keine C#-Programme, um mal eben 30 Benutzer anzulegen.

    Fehlerarten im Vorgriff

    Ein Syntaxfehler verletzt die Regeln der Sprache. Den findet der Compiler. Ein Laufzeitfehler tritt erst beim Ausführen auf, etwa wenn jemand „abc“ eintippt, wo eine Zahl erwartet wird. Ein logischer Fehler rechnet einfach falsch, ohne dass irgendwer meckert. Der Compiler sagt bei vielem nein. Bei Logik sagt er leider gar nichts.

    START IN ZEITLUPEKlicke dich Zeile für Zeile durch das Programm.
    Typische Fallen: „C# ist eine interpretierte Sprache, weil da ein JIT drin ist.“ Nicht ganz: C# wird kompiliert, zweimal sogar. Erst in IL, beim Start dann per JIT in Maschinencode. Ein Syntaxfehler stoppt das Programm deshalb immer vor dem Start.

    Aufbau eines C#-Programms

    Du liest ein kleines Programm und weißt, wofür jedes Zeichen darin steht.

    Jetzt wird es konkret. Ein C#-Programm besteht aus Anweisungen. Jede Anweisung ist ein Befehl, zum Beispiel „schreibe diese Zeile“. Am Ende jeder Anweisung steht ein Semikolon. Es ist der Punkt am Satzende. Fehlt er, hat der Compiler Redebedarf.

    Mehrere Anweisungen kannst du in geschweiften Klammern { } zu einem Block zusammenfassen. Alles hinter // ist ein Kommentar: Der Compiler ignoriert ihn, dein Kollege in sechs Monaten zum Glück nicht.

    Console.WriteLine("Hallo Welt!"); │ │ │ │ └ Semikolon: Anweisung zu Ende │ │ │ └ Text in doppelten Anführungszeichen │ │ └ Methode: „schreibe eine Zeile“ │ └ Punkt: greift auf etwas zu, das zu Console gehört └ Klasse aus .NET für das Konsolenfenster
    Jede Anweisung endet mit ;. Text steht in doppelten Anführungszeichen. Groß- und Kleinschreibung zählt: console ist nicht Console.
    VORGEMACHT
    Wir zerlegen die berühmteste Zeile der Programmierwelt:
    Console.WriteLine("Hallo Welt!");
    1. Console ist das Konsolenfenster, genauer: eine fertige Klasse aus .NET.
    2. Der Punkt heißt „gehe in“. Du greifst damit auf etwas zu, das zu Console gehört.
    3. WriteLine ist eine Methode, also ein Befehl mit Namen. Sie schreibt eine Zeile und springt danach in die nächste.
    4. Die runden Klammern übergeben, womit die Methode arbeiten soll. Hier ist es der Text "Hallo Welt!".
    5. Das Semikolon beendet die Anweisung.

    Lesen, schreiben, kommentieren

    Console.ReadLine() wartet, bis jemand etwas tippt und Enter drückt, und liefert den Text zurück. Console.Write() schreibt ohne Zeilenumbruch.

    // Fragt nach dem Namen und begrüßt
Console.Write("Name: ");
string? name = Console.ReadLine();
Console.WriteLine("Hallo " + name);

    Zwei Formen desselben Programms

    Neue .NET-Projekte erlauben „Top-Level-Anweisungen“: Du schreibst die Befehle direkt in die Datei. In älteren Büchern und in vielen Prüfungsaufgaben steht drumherum noch eine Klasse mit der Methode Main. Dort beginnt das Programm. Das ist dasselbe Programm mit mehr Verpackung.

    class Program
{
    static void Main()
    {
        Console.WriteLine("Hallo Welt!");
    }
}

    Datentypen

    Du wählst für jeden Wert den passenden Datentyp und kennst seine Grenzen.

    Im Speicher liegt alles als Nullen und Einsen. Das Bitmuster 01000001 kann die Zahl 65 sein oder der Buchstabe A. Woher weiß das Programm, was gemeint ist? Durch den Datentyp.

    Der Datentyp legt drei Dinge fest: welche Werte erlaubt sind, wie viel Speicher dafür reserviert wird und was man damit tun kann. Mit Zahlen rechnest du, Texte hängst du aneinander. Andersherum wird es lustig, aber selten richtig.

    C# ist streng typisiert: Jeder Wert hat einen festen Typ, und der Compiler prüft das. Text in eine Zahl stopfen? Compiler sagt nein.

    TypInhaltGrößeBeispiel
    intganze Zahl, ca. ±2,1 Milliarden32 Bit24
    longgroße ganze Zahl64 Bit8000000000L
    doubleKommazahl, nicht immer exakt64 Bit3.5
    decimalexakte Dezimalzahl, etwa für Geld128 Bit19.99m
    boolwahr oder falsch1 Bytetrue
    chargenau ein Zeichen16 Bit'A'
    stringText, beliebig langje nach Länge"Router"
    Ganze Zahl → int. Geld → decimal mit m. Messwert mit Komma → double. Ja/Nein → bool. Ein Zeichen in '…' → char. Text in "…" → string. Im Code steht das Komma als Punkt: 3.5.
    VORGEMACHT
    Derselbe Inhalt, drei verschiedene Typen:
    int zahl = 40;
string text = "40";
double komma = 40.0;
Console.WriteLine(zahl + 2);
Console.WriteLine(text + 2);
Console.WriteLine(komma / 3);
    1. zahl ist ein int. Plus 2 wird gerechnet: 42.
    2. text ist ein string. Plus 2 wird angehängt: „402“. Der Typ entscheidet, was + bedeutet.
    3. komma ist ein double. Die Division liefert Nachkommastellen.
    4. Ein deutsches Windows zeigt dabei ein Komma statt eines Punktes. Im Quelltext steht immer der Punkt.

    Wertebereich und Überlauf

    Ein int hat 32 Bit. Damit passen Zahlen von −2.147.483.648 bis 2.147.483.647 hinein. Was passiert eine Zahl darüber? Standardmäßig springt C# ohne Warnung ans andere Ende. Das nennt man Überlauf.

    int maximum = int.MaxValue;
maximum = maximum + 1;
Console.WriteLine(maximum);

    Für größere Werte gibt es long mit 64 Bit. Dateigrößen in Byte oder Weltbevölkerung? long.

    Warum Geld decimal braucht

    double speichert Zahlen binär. Viele Dezimalbrüche wie 0,1 lassen sich so nicht exakt darstellen. Für Messwerte ist der winzige Fehler egal. Für Rechnungen nicht.

    double d = 0.1 + 0.2;
decimal m = 0.1m + 0.2m;
Console.WriteLine(d == 0.3);
Console.WriteLine(m == 0.3m);

    char und string

    'A' in einfachen Anführungszeichen ist ein Zeichen. "A" in doppelten ist ein Text, der zufällig ein Zeichen lang ist. Für den Compiler zwei verschiedene Typen.

    char zeichen = "A";

    Wertetypen und Verweistypen

    int, double, bool und char sind Wertetypen: Die Variable enthält den Wert selbst. string ist ein Verweistyp: Die Variable zeigt auf einen Text im Speicher. Für den Einstieg reicht: Beides funktioniert, wie du es erwartest. Der Unterschied wird später bei Objekten wichtig.

    TYPEN IN ZEITLUPEKlicke dich Zeile für Zeile durch das Programm.
    Typische Fallen: decimal-Werte brauchen das m: 19.99m. Ohne Suffix ist 19.99 ein double, und der Compiler verweigert die Zuweisung. Und int.MaxValue + 1 gibt keine Fehlermeldung, sondern eine sehr negative Überraschung.

    Variablen deklarieren und initialisieren

    Du unterscheidest Deklaration, Initialisierung und Zuweisung sicher und schreibst sie selbst.

    Eine Variable ist eine beschriftete Schublade im Speicher. Der Datentyp sagt, was hineinpasst, der Name steht auf dem Etikett. Mit Variablen passieren drei verschiedene Dinge, und die Prüfung fragt gern genau danach:

    1. Deklarieren: Die Schublade wird angelegt. int ports; Typ und Name, sonst nichts.
    2. Initialisieren: Die Schublade bekommt ihren ersten Wert. ports = 24;
    3. Zuweisen: Später kommt ein neuer Wert hinein, der alte fliegt raus. ports = 48;

    Meist erledigst du die ersten beiden in einer Zeile: int ports = 24; Deklaration mit Initialisierung.

    int ports; Deklaration Schublade „ports“ für int, noch leer ports = 24; Initialisierung erster Wert: 24 ports = 48; Zuweisung neuer Wert, 24 ist weg int vlan = 10; Deklaration + Initialisierung in einer Zeile
    Steht ein Typ vorne, wird deklariert. Steht nur Name = Wert, wird zugewiesen. Lesen darfst du eine Variable erst, wenn sie einen Wert hat. Jeder Name darf im selben Bereich nur einmal deklariert werden.
    VORGEMACHT
    Die drei Schritte, einzeln und sauber:
    int ports;
ports = 24;
Console.WriteLine(ports);
ports = 48;
Console.WriteLine(ports);
    1. int ports; deklariert die Variable. Sie hat noch keinen Wert, den man lesen dürfte.
    2. ports = 24; initialisiert sie mit dem ersten Wert.
    3. Die Ausgabe zeigt 24.
    4. ports = 48; ist eine Zuweisung. Kein Typ davor, denn die Schublade gibt es schon.
    5. Die zweite Ausgabe zeigt 48. Die 24 ist weg, ohne Abschiedsbrief.

    Lesen vor dem ersten Wert

    C# lässt dich eine lokale Variable nicht lesen, bevor sie einen Wert hat. Der Compiler meldet CS0165: Verwendung der nicht zugewiesenen lokalen Variable. Er hat recht: In der Schublade liegt noch nichts Sinnvolles.

    int fehler;
Console.WriteLine(fehler);

    Doppelt deklariert

    Zweimal dieselbe Schublade anlegen geht nicht. Wer nur einen neuen Wert will, lässt den Typ weg.

    int vlan = 10;
int vlan = 20;

    Gute Namen

    Ein Name beginnt mit einem Buchstaben oder Unterstrich, danach dürfen Buchstaben, Ziffern und Unterstriche folgen. Keine Leerzeichen, keine Bindestriche, keine reservierten Wörter wie class oder int. Üblich ist camelCase: freiePorts, anzahlGeraete. Und bitte nicht x2, außer du willst dein zukünftiges Ich ärgern.

    var und const

    Bei var leitet der Compiler den Typ aus dem Startwert ab. Deshalb braucht var immer eine Initialisierung. Der Typ bleibt danach fest. const macht einen Wert unveränderlich, er muss sofort feststehen.

    var hersteller = "Contoso";
const int MaxPorts = 48;
Console.WriteLine(hersteller + " " + MaxPorts);

    Werte tauschen

    Zwei Variablen tauschen ihre Inhalte? Dafür brauchst du eine dritte Schublade als Zwischenablage. Sonst ist ein Wert verloren.

    int a = 1;
int b = 2;
int tmp = a;
a = b;
b = tmp;
Console.WriteLine(a + " " + b);
    SCHUBLADEN IN ZEITLUPEKlicke dich Zeile für Zeile durch das Programm.
    Typische Fallen: int ports = 24; und später nochmal int ports = 48;? Doppelte Deklaration, Compiler sagt nein. Und var x; ohne Wert geht auch nicht: Woher soll der Compiler den Typ kennen? Raten ist nicht sein Ding.

    Typumwandlung, Ein- und Ausgabe

    Du bringst Eingaben in den richtigen Typ und gibst Werte sauber aus.

    Die Tastatur liefert immer Text. Tippt jemand 42, bekommst du den string „42“, nicht die Zahl 42. Rechnen willst du aber mit Zahlen. Also musst du umwandeln.

    Manche Umwandlungen macht C# von selbst, weil dabei nichts verloren geht: implizit. Eine kleine Zahl passt immer in eine große Schublade. Bei anderen könnte etwas verloren gehen. Die musst du explizit verlangen, damit klar ist: Du weißt, was du tust. Zumindest offiziell.

    implizit (automatisch, sicher) int → long → double int → decimal explizit (Cast, kann abschneiden) (int)3.9 → 3 Text → Zahl int.Parse("42") double.Parse("3.5") Text → Zahl, ohne Absturz int.TryParse(text, out int zahl) Zahl → Text zahl.ToString() oder $"{zahl}"
    Console.ReadLine() liefert string. Mit int.Parse wird Text zur Zahl. (int) vor einem double schneidet ab, statt zu runden. $"…{wert}…" setzt Werte in Text ein.
    VORGEMACHT
    Eingabe lesen, umwandeln, rechnen, ausgeben:
    Console.WriteLine("Wie viele Geräte?");
string eingabe = Console.ReadLine()!;
int anzahl = int.Parse(eingabe);
double proRaum = anzahl / 4.0;
Console.WriteLine($"{anzahl} Geräte, {(int)proRaum} volle pro Raum");
    1. ReadLine liefert den Text „10“.
    2. int.Parse macht daraus die Zahl 10.
    3. 10 / 4.0 ist wegen 4.0 eine double-Division: 2,5.
    4. (int)proRaum schneidet ab: 2. Gerundet wird nicht.
    5. Das $ vor dem Text erlaubt Platzhalter in { }. Das heißt String-Interpolation.

    Implizit und explizit

    Von int nach long oder double geht nichts verloren, das passiert automatisch. Umgekehrt muss ein Cast her: der Zieltyp in runden Klammern.

    int klein = 7;
long gross = klein;
double kommazahl = klein;
double messung = 9.99;
int abgeschnitten = (int)messung;
Console.WriteLine(gross + " " + kommazahl + " " + abgeschnitten);
    double messung = 9.99;
int wert = messung;

    Parse und TryParse

    int.Parse("abc") kompiliert problemlos und stürzt beim Ausführen mit einer FormatException ab. Ein klassischer Laufzeitfehler. int.TryParse versucht es höflicher: Es liefert true oder false und legt die Zahl bei Erfolg in die out-Variable.

    string eingabe = "abc";
if (int.TryParse(eingabe, out int zahl))
{
    Console.WriteLine(zahl * 2);
}
else
{
    Console.WriteLine("Das ist keine Zahl.");
}

    Text zusammensetzen

    Drei Wege führen zum selben Ergebnis. Interpolation ist meist am lesbarsten.

    string name = "NAS-3";
int frei = 512;
Console.WriteLine(name + ": " + frei + " GB frei");
Console.WriteLine($"{name}: {frei} GB frei");
Console.WriteLine(name + ": " + frei.ToString() + " GB frei");

    Achtung bei +: C# arbeitet von links nach rechts. "Summe: " + 2 + 3 ergibt „Summe: 23“, weil links schon Text steht. "Summe: " + (2 + 3) ergibt „Summe: 5“.

    Operatoren und Berechnungen

    Du rechnest Ausdrücke so aus, wie C# sie ausrechnet.

    Ein Backup hat 10 GB, drei Festplatten sollen es sich teilen. 10 / 3 ergibt in C# 3. Kein Bug: Zwei int-Werte ergeben eine Integerdivision, und der Nachkommateil wird abgeschnitten. Niemand hat dich gefragt, ob du den Rest noch brauchst.

    + − * / Rechnen % Rest der Division (Modulo) == != < > <= >= Vergleichen, Ergebnis ist bool && || ! und, oder, nicht = += -= ++ -- Zuweisen und Ändern
    Sind beide Werte int, ist das Ergebnis int. Ist einer double, gibt es Nachkommastellen. Punkt vor Strich gilt auch hier, Klammern gehen vor.
    VORGEMACHT
    Wie viele volle 3er-Pakete passen in 10 Geräte, und wie viele bleiben übrig?
    int geraete = 10;
Console.WriteLine(geraete / 3);
Console.WriteLine(geraete % 3);
Console.WriteLine(geraete / 3.0 > 3);
    1. 10 / 3: beide int, also 3 mit abgeschnittenem Rest.
    2. 10 % 3: 3 × 3 = 9, es bleibt 1. Modulo liefert genau diesen Rest.
    3. 3.0 ist ein double, also wird echt geteilt: etwa 3,33.
    4. 3,33 ist größer als 3. Der Vergleich ergibt True.

    Abkürzungen beim Zuweisen

    x += 5 bedeutet x = x + 5. x++ erhöht um 1. Steht das ++ hinter der Variablen, liefert der Ausdruck noch den alten Wert. Steht es davor, den neuen.

    int x = 5;
Console.WriteLine(x++);
Console.WriteLine(x);
Console.WriteLine(++x);

    Logik

    && ist nur wahr, wenn beide Seiten wahr sind. || reicht eine wahre Seite. ! dreht um. && wird vor || ausgewertet.

    bool online = true;
bool wartung = false;
Console.WriteLine(online && !wartung);

    Rangfolge

    Reihenfolge von oben nach unten: Klammern, dann * / %, dann + -, dann Vergleiche, dann &&, dann ||, zuletzt die Zuweisung.

    RECHNUNG IN ZEITLUPEKlicke dich Zeile für Zeile durch das Programm.
    Typische Fallen: double d = 10 / 4; ergibt 2, nicht 2,5. Rechts wird zuerst mit int gerechnet, erst danach landet die 2 im double. Die Variable kann nichts dafür.

    Verzweigungen

    Du sagst vorher, welcher Zweig eines Programms läuft.

    Freier Plattenplatz unter 10 %? Dann Warnung. Sonst alles gut. Genau das macht if: Es prüft einen Ausdruck, der true oder false ergibt, und entscheidet, welcher Block läuft.

    if (Bedingung) → true → erster Block → false → else-Block Danach läuft das Programm normal weiter.
    Die Bedingung steht in runden Klammern und muss ein bool ergeben. Vergleichen heißt ==, nicht =. Bei else if läuft nur der erste passende Zweig.
    VORGEMACHT
    Der Türsteher des Serverraums:
    int alter = 17;

if (alter >= 18)
{
    Console.WriteLine("Zutritt erlaubt.");
}
else
{
    Console.WriteLine("Nö. Erst erwachsen werden.");
}
    1. alter enthält 17.
    2. Das Programm prüft 17 >= 18. Das ist false.
    3. Der erste Block wird übersprungen, der else-Block läuft.
    4. Danach geht es unter der letzten Klammer weiter. Hier ist das Programm zu Ende.

    else if

    Die Zweige werden von oben geprüft. Der erste Treffer gewinnt, der Rest wird nicht mehr angesehen. Die Reihenfolge entscheidet also mit.

    int frei = 8;
if (frei < 5)
{
    Console.WriteLine("Kritisch");
}
else if (frei < 10)
{
    Console.WriteLine("Warnung");
}
else
{
    Console.WriteLine("OK");
}

    switch

    Passt, wenn ein einziger Wert mit festen Möglichkeiten verglichen wird, etwa ein Menü. break beendet den Fall, default fängt alles andere auf.

    string wahl = "2";
switch (wahl)
{
    case "1":
        Console.WriteLine("Neues Gerät");
        break;
    case "2":
        Console.WriteLine("Liste anzeigen");
        break;
    default:
        Console.WriteLine("Unbekannt");
        break;
}

    Der Klassiker

    = weist zu, == vergleicht. C# fängt die Verwechslung hier ab, weil das Ergebnis kein bool ist:

    int x = 5;
if (x = 5)
{

}

    Typische Fallen: Text vergleichst du mit == exakt: "Ja" == "ja" ist false. Und wer wert < 10 vor wert < 5 prüft, sieht den Zweig „Kritisch“ nie.

    Schleifen

    Du sagst genau, wie oft eine Schleife läuft und warum.

    Zehn Geräte anpingen, zehnmal dieselbe Zeile schreiben? Spätestens bei 500 Geräten kündigst du. Eine Schleife wiederholt einen Block, solange eine Bedingung gilt.

    for (Start; Bedingung; Schritt) 1. Start läuft einmal 2. Bedingung true? Sonst Ende 3. Block läuft 4. Schritt läuft, weiter bei 2
    Durchläufe zählst du, indem du die Werte der Zählvariablen aufschreibst. Bei i < 10 mit Start 0 sind es zehn, bei i <= 10 elf.
    VORGEMACHT
    Eine Meldung für drei Ports:
    for (int i = 1; i <= 3; i++)
{
    Console.WriteLine("Port " + i);
}
    1. int i = 1 läuft genau einmal.
    2. 1 <= 3 ist wahr, also läuft der Block: „Port 1“.
    3. i++ macht aus 1 eine 2. Dann wieder prüfen.
    4. Das passiert noch für 2 und 3. Danach ist i 4, und 4 <= 3 ist falsch. Schluss.

    while und do while

    while prüft vor dem Block und läuft vielleicht nie. do while prüft danach und läuft mindestens einmal.

    int n = 5;
while (n < 3)
{
    Console.WriteLine("while");
    n++;
}
do
{
    Console.WriteLine("do");
    n++;
} while (n < 3);

    foreach

    Geht jedes Element einer Sammlung durch. Ohne Zähler, ohne Indexfehler, ohne Drama.

    string[] geraete = { "Router", "Switch" };
foreach (string g in geraete)
{
    Console.WriteLine(g);
}

    break und continue

    break verlässt die Schleife ganz. continue springt direkt zum nächsten Durchlauf.

    for (int i = 1; i <= 5; i++)
{
    if (i == 2) continue;
    if (i == 4) break;
    Console.WriteLine(i);
}

    Endlosschleifen

    Ändert sich die Bedingung nie, läuft die Schleife bis zum Abbruch. Im Terminal stoppt Strg+C das Programm. Der Lüfter dankt.

    SCHLEIFE IN ZEITLUPEKlicke dich Zeile für Zeile durch das Programm.
    Typische Fallen: Off-by-one: <= statt < liefert einen Durchlauf zu viel. Und bei while das Hochzählen zu vergessen, ist die häufigste Art, eine CPU zu heizen.

    Arrays und erste Methoden

    Du greifst auf Elemente eines Arrays zu und rufst kleine Methoden auf.

    Für 200 Geräte willst du keine 200 Variablen. Ein Array hält mehrere Werte gleichen Typs mit fester Größe. Eine Liste kann wachsen und schrumpfen. Beide nummerieren ihre Elemente mit einem Index, und der beginnt bei 0. Nicht bei 1. Nie. Auch nicht montags.

    Und wenn du dieselbe Berechnung an fünf Stellen brauchst, schreibst du sie einmal als Methode: ein benannter Codeblock, den du beliebig oft aufrufst. Einmal reparieren, überall behoben. Damit hast du alle Bausteine für ein erstes kleines Tool.

    namen "Router" "Switch" "Firewall" Index 0 1 2 Length = 3, letzter gültiger Index = 2 static int Doppelt (int x) │ │ │ └ Parameter: was hineinkommt │ │ └ Name │ └ Rückgabetyp: was herauskommt └ gehört zum Programm, nicht zu einem Objekt
    Letzter Index = Anzahl − 1. Arrays nennen die Anzahl Length, Listen Count. Eine Methode mit Rückgabetyp braucht return. void heißt: gibt nichts zurück.
    VORGEMACHT
    Ein Array, eine Schleife und eine Methode arbeiten zusammen:
    static bool IstVoll(int belegt, int ports)
{
    return belegt >= ports;
}

string[] namen = { "SW-1", "SW-2", "SW-3" };
int[] belegt = { 24, 18, 24 };
for (int i = 0; i < namen.Length; i++)
{
    if (IstVoll(belegt[i], 24))
    {
        Console.WriteLine(namen[i] + " ist voll");
    }
}
    1. Zwei Arrays: Index 0 gehört zu SW-1, Index 1 zu SW-2, Index 2 zu SW-3.
    2. Die Schleife läuft von 0 bis Length − 1, also bis 2.
    3. Bei jedem Durchlauf wird IstVoll aufgerufen. Die Werte landen in den Parametern belegt und ports.
    4. return liefert true oder false an die Aufrufstelle zurück.
    5. Nur bei true erscheint eine Meldung: SW-1 und SW-3.

    Arrays anlegen

    Mit festen Werten oder mit einer Größe. Neue int-Elemente enthalten 0, neue string-Elemente null.

    int[] werte = new int[3];
werte[0] = 5;
werte[2] = 7;
Console.WriteLine(werte[0] + werte[1] + werte[2]);

    Methoden: Ausgeben ist nicht Zurückgeben

    Eine void-Methode tut etwas, etwa eine Meldung ausgeben. Eine Methode mit Rückgabetyp liefert einen Wert, mit dem du weiterarbeitest.

    static void Melde(string text)
{
    Console.WriteLine("Hinweis: " + text);
}

static int Summe(int a, int b)
{
    return a + b;
}

Melde("Backup fertig");
Console.WriteLine(Summe(2, 3) * 10);

    Die Werte beim Aufruf heißen Argumente, die Platzhalter in der Methode Parameter. Die Zuordnung erfolgt über die Reihenfolge, nicht über den Namen.
