    01

    Willkommen in C#

    Ein kleines Programm lesen und jedes Zeichen darin erklären.

    Dein Chef will ein kleines Tool, das Geräte erfasst. Du tippst dafür Text in eine Datei, und am Ende läuft ein Programm. Dazwischen sitzt jemand, der sehr genau liest: der Compiler. Er übersetzt deinen Quelltext in eine Form, die .NET ausführen kann. Findet er einen Fehler, bricht er ab und nennt dir die Stelle.

    C# ist die Sprache, in der du schreibst. .NET ist die Plattform darunter: Sie führt das Programm aus und bringt fertige Bausteine wie Console mit. Vergleich gefällig? C# ist die Sprache, in der du die Bestellung aufgibst. .NET ist die Küche samt Personal.

    Man baut damit Windows-Tools, Webserver, Spiele und Automatisierungen. Auch als Systemintegrator triffst du es: Wer ein Admin-Tool anpassen muss, sollte es wenigstens lesen können.

    Quelltext (.cs) → Compiler → Programm → .NET führt es aus → Ausgabe in der Konsole
    Jede Anweisung endet mit ;. Text steht in doppelten Anführungszeichen. Groß- und Kleinschreibung zählt: console ist nicht Console.
    VORGEMACHT
    Wir zerlegen die berühmteste Zeile der Programmierwelt:
    Console.WriteLine("Hallo Welt!");
    1. Console ist das Konsolenfenster, genauer: eine fertige Klasse aus .NET.
    2. Der Punkt heißt „gehe in“. Du greifst damit auf etwas zu, das zu Console gehört.
    3. WriteLine ist eine Methode, also ein Befehl mit Namen. Sie schreibt eine Zeile und springt danach in die nächste.
    4. Die runden Klammern übergeben, womit die Methode arbeiten soll. Hier ist es der Text "Hallo Welt!".
    5. Das Semikolon beendet die Anweisung. Ohne dieses Zeichen hat der Compiler sofort Redebedarf.

    Lesen, schreiben, kommentieren

    Console.ReadLine() wartet, bis jemand etwas tippt und Enter drückt, und liefert den Text zurück. Console.Write() schreibt ohne Zeilenumbruch. Alles hinter // ist ein Kommentar: Der Compiler ignoriert ihn, dein Kollege in sechs Monaten nicht.

    // Fragt nach dem Namen und begrüßt
Console.Write("Name: ");
string? name = Console.ReadLine();
Console.WriteLine("Hallo " + name);

    Zwei Formen desselben Programms

    Neue .NET-Projekte erlauben „Top-Level-Anweisungen“: Du schreibst die Befehle direkt in die Datei. In älteren Büchern steht drumherum noch eine Klasse mit Main. Das ist dasselbe Programm mit mehr Verpackung.

    class Program
{
    static void Main()
    {
        Console.WriteLine("Hallo Welt!");
    }
}

    Variablen und Datentypen

    Für jeden Wert den passenden Datentyp wählen.

    Dein Tool soll sich merken, dass Switch-07 genau 24 Ports hat. Dafür brauchst du eine Variable: eine beschriftete Schublade für einen Wert. Der Datentyp legt fest, was hineindarf.

    C# achtet streng darauf. Versuch mal, einen Text in eine Schublade für ganze Zahlen zu stopfen. Das Programm startet dann gar nicht erst.

    TypInhaltBeispiel
    intganze Zahl24
    doubleKommazahl, nicht immer exakt3.5
    decimalexakte Dezimalzahl, etwa für Geld19.99m
    stringText"Router"
    chargenau ein Zeichen'A'
    boolwahr oder falschtrue
    Aufbau: Typ name = Wert;. Text in "…", ein Zeichen in '…', Kommazahlen mit Punkt. "40" ist Text, 40 ist eine Zahl.
    VORGEMACHT
    Drei Schubladen, drei Inhalte. Danach ändern wir eine davon:
    int ports = 24;
string name = "Switch-07";
bool aktiv = true;
ports = 48;
Console.WriteLine(name + " hat " + ports + " Ports. Aktiv: " + aktiv);
    1. int ports = 24; legt die Variable an (Deklaration) und füllt sie gleich (Initialisierung).
    2. Bei ports = 48; steht kein Typ mehr. Die Schublade gibt es schon, der alte Inhalt fliegt raus.
    3. Das + zwischen Text und Zahl hängt beides zu einem Text zusammen.
    4. Ein bool erscheint in der Ausgabe als True oder False, mit großem Anfangsbuchstaben.

    Warum 40 nicht „40“ ist

    40 + 2 ergibt 42. "40" + "2" ergibt 402. Bei Text bedeutet + Aneinanderhängen. Und das hier scheitert schon beim Kompilieren:

    int alter = "40";

    var und const

    Bei var leitet der Compiler den Typ aus dem Wert ab. Die Variable bleibt trotzdem fest typisiert. const macht einen Wert unveränderlich.

    var hersteller = "Contoso"; // ist ein string
const int MaxPorts = 48;
Console.WriteLine(hersteller + " " + MaxPorts);

    Eingaben umwandeln

    ReadLine() liefert immer Text, auch wenn jemand 42 tippt. Rechnen kannst du erst nach dem Umwandeln. Beim Umwandeln einer Kommazahl in int mit (int) wird abgeschnitten, nicht gerundet.

    string eingabe = "42";
int zahl = int.Parse(eingabe);
Console.WriteLine(zahl + 1);
Console.WriteLine((int)3.9);
    SCHUBLADEN IN ZEITLUPEKlicke dich Zeile für Zeile durch das Programm.
    Typische Fallen: decimal-Werte brauchen das m: 19.99m. Ohne das Suffix ist die Zahl ein double, und der Compiler verweigert die Zuweisung.

    Operatoren und Berechnungen

    Ausdrücke so auswerten, wie C# sie auswertet.

    Ein Backup hat 10 GB, drei Festplatten sollen es sich teilen. 10 / 3 ergibt in C# 3. Kein Bug: Zwei int-Werte ergeben eine Integerdivision, und der Nachkommateil wird abgeschnitten. Niemand hat dich gefragt, ob du den Rest noch brauchst.

    + − * / Rechnen % Rest der Division (Modulo) == != < > <= >= Vergleichen, Ergebnis ist bool && || ! und, oder, nicht = += -= ++ -- Zuweisen und Ändern
    Sind beide Werte int, ist das Ergebnis int. Ist einer double, gibt es Nachkommastellen. Punkt vor Strich gilt auch hier, Klammern gehen vor.
    VORGEMACHT
    Wie viele volle 3er-Pakete passen in 10 Geräte, und wie viele bleiben übrig?
    int geraete = 10;
Console.WriteLine(geraete / 3);
Console.WriteLine(geraete % 3);
Console.WriteLine(geraete / 3.0 > 3);
    1. 10 / 3: beide int, also 3 mit abgeschnittenem Rest.
    2. 10 % 3: 3 × 3 = 9, es bleibt 1. Modulo liefert genau diesen Rest.
    3. 3.0 ist ein double, also wird echt geteilt: etwa 3,33.
    4. 3,33 ist größer als 3. Der Vergleich ergibt True.

    Abkürzungen beim Zuweisen

    x += 5 bedeutet x = x + 5. x++ erhöht um 1. Steht das ++ hinter der Variablen, liefert der Ausdruck noch den alten Wert. Steht es davor, den neuen.

    int x = 5;
Console.WriteLine(x++);
Console.WriteLine(x);
Console.WriteLine(++x);

    Logik

    && ist nur wahr, wenn beide Seiten wahr sind. || reicht eine wahre Seite. ! dreht um. && wird vor || ausgewertet.

    bool online = true;
bool wartung = false;
Console.WriteLine(online && !wartung);

    Rangfolge

    Reihenfolge von oben nach unten: Klammern, dann * / %, dann + -, dann Vergleiche, dann &&, dann ||, zuletzt die Zuweisung.

    RECHNUNG IN ZEITLUPEKlicke dich Zeile für Zeile durch das Programm.
    Typische Fallen: double d = 10 / 4; ergibt 2, nicht 2,5. Rechts wird zuerst mit int gerechnet, erst danach landet die 2 im double. Die Variable kann nichts dafür.

    Auf deinem Rechner ausprobieren

    Bedingungen und Entscheidungen

    Vorhersagen, welcher Zweig eines Programms läuft.

    Freier Plattenplatz unter 10 %? Dann Warnung. Sonst alles gut. Genau das macht if: Es prüft einen Ausdruck, der true oder false ergibt, und entscheidet, welcher Block läuft.

    if (Bedingung) → true → erster Block → false → else-Block Danach läuft das Programm normal weiter.
    Die Bedingung steht in runden Klammern und muss ein bool ergeben. Vergleichen heißt ==, nicht =. Bei else if läuft nur der erste passende Zweig.
    VORGEMACHT
    Der Türsteher des Serverraums:
    int alter = 17;

if (alter >= 18)
{
    Console.WriteLine("Zutritt erlaubt.");
}
else
{
    Console.WriteLine("Nö. Erst erwachsen werden.");
}
    1. alter enthält 17.
    2. Das Programm prüft 17 >= 18. Das ist false.
    3. Der erste Block wird übersprungen, der else-Block läuft.
    4. Danach geht es unter der letzten Klammer weiter. Hier ist das Programm zu Ende.

    else if

    Die Zweige werden von oben geprüft. Der erste Treffer gewinnt, der Rest wird nicht mehr angesehen. Die Reihenfolge entscheidet also mit.

    int frei = 8;
if (frei < 5)
{
    Console.WriteLine("Kritisch");
}
else if (frei < 10)
{
    Console.WriteLine("Warnung");
}
else
{
    Console.WriteLine("OK");
}

    switch

    Passt, wenn ein einziger Wert mit festen Möglichkeiten verglichen wird, etwa ein Menü. break beendet den Fall, default fängt alles andere auf.

    string wahl = "2";
switch (wahl)
{
    case "1":
        Console.WriteLine("Neues Gerät");
        break;
    case "2":
        Console.WriteLine("Liste anzeigen");
        break;
    default:
        Console.WriteLine("Unbekannt");
        break;
}

    Der Klassiker

    = weist zu, == vergleicht. C# fängt die Verwechslung hier ab, weil das Ergebnis kein bool ist:

    int x = 5;
if (x = 5)
{
    Console.WriteLine("fünf");
}
    ENTSCHEIDUNG IN ZEITLUPEKlicke dich Zeile für Zeile durch das Programm.
    Typische Fallen: Text vergleichst du mit == exakt: "Ja" == "ja" ist false. Und wer wert < 10 vor wert < 5 prüft, sieht den Zweig „Kritisch“ nie.

    Schleifen

    Genau sagen, wie oft eine Schleife läuft und warum.

    Zehn Geräte anpingen, zehnmal dieselbe Zeile schreiben? Spätestens bei 500 Geräten kündigst du. Eine Schleife wiederholt einen Block, solange eine Bedingung gilt.

    for (Start; Bedingung; Schritt) 1. Start läuft einmal 2. Bedingung true? Sonst Ende 3. Block läuft 4. Schritt läuft, weiter bei 2
    Durchläufe zählst du, indem du die Werte der Zählvariablen aufschreibst. Bei i < 10 mit Start 0 sind es zehn, bei i <= 10 elf.
    VORGEMACHT
    Eine Meldung für drei Ports:
    for (int i = 1; i <= 3; i++)
{
    Console.WriteLine("Port " + i);
}
    1. int i = 1 läuft genau einmal.
    2. 1 <= 3 ist wahr, also läuft der Block: „Port 1“.
    3. i++ macht aus 1 eine 2. Dann wieder prüfen.
    4. Das passiert noch für 2 und 3. Danach ist i 4, und 4 <= 3 ist falsch. Schluss.

    while und do while

    while prüft vor dem Block und läuft vielleicht nie. do while prüft danach und läuft mindestens einmal.

    int n = 5;
while (n < 3)
{
    Console.WriteLine("while");
    n++;
}
do
{
    Console.WriteLine("do");
    n++;
} while (n < 3);

    foreach

    Geht jedes Element einer Sammlung durch. Ohne Zähler, ohne Indexfehler, ohne Drama.

    string[] geraete = { "Router", "Switch" };
foreach (string g in geraete)
{
    Console.WriteLine(g);
}

    break und continue

    break verlässt die Schleife ganz. continue springt direkt zum nächsten Durchlauf.

    for (int i = 1; i <= 5; i++)
{
    if (i == 2) continue;
    if (i == 4) break;
    Console.WriteLine(i);
}

    Endlosschleifen

    Ändert sich die Bedingung nie, läuft die Schleife bis zum Abbruch. Im Terminal stoppt Strg+C das Programm. Der Lüfter dankt.

    SCHLEIFE IN ZEITLUPEKlicke dich Zeile für Zeile durch das Programm.
    Typische Fallen: Off-by-one: <= statt < liefert einen Durchlauf zu viel. Und bei while das Hochzählen zu vergessen, ist die häufigste Art, eine CPU zu heizen.

    Auf deinem Rechner ausprobieren

    Gib die Zahlen von 1 bis 10 aus. Danach versuche es mit while statt for.

    Musterlösung ansehen

{
    Console.WriteLine(i);

    Arrays, Listen und Zeichenketten

    Auf Elemente von Sammlungen sicher zugreifen.

    Für 200 Geräte willst du keine 200 Variablen. Ein Array hält mehrere Werte gleichen Typs mit fester Größe. Eine Liste kann wachsen und schrumpfen. Beide nummerieren ihre Elemente mit einem Index, und der beginnt bei 0.

    Warum bei 0? Der Index sagt, wie weit das Element vom Anfang entfernt ist. Das erste ist 0 Schritte entfernt. Klingt nach Informatikerlogik, ist es auch.

    namen "Router" "Switch" "Firewall" Index 0 1 2 Length = 3, letzter gültiger Index = 2
    Letzter Index = Anzahl − 1. Arrays nennen die Anzahl Length, Listen Count. Beides ohne Klammern.
    VORGEMACHT
    Warum steht hier „Switch“?
    string[] namen = { "Router", "Switch", "Firewall" };

Console.WriteLine(namen[1]);
    1. Das Array enthält drei Texte.
    2. Index 0 ist Router, Index 1 ist Switch, Index 2 ist Firewall.
    3. namen[1] liefert also das zweite Element.
    4. namen[3] gäbe es nicht. Das Programm würde mit einer IndexOutOfRangeException abstürzen.

    Listen

    List<string> ist eine Liste von Texten. Das T in List<T> steht für den Elementtyp. Add hängt an, Remove entfernt das erste passende Element.

    List<string> geraete = new List<string>();
geraete.Add("Router");
geraete.Add("Switch");
geraete.Remove("Router");
Console.WriteLine(geraete.Count);
Console.WriteLine(geraete[0]);

    Zeichenketten

    Ein string kennt nützliche Methoden. Sie verändern den Text nicht, sondern liefern einen neuen. Mit dem $ vor dem Text setzt du Werte direkt ein: String-Interpolation.

    string name = "Switch";
int ports = 24;
Console.WriteLine(name.Length);
Console.WriteLine(name.ToUpper());
Console.WriteLine(name.Contains("wit"));
Console.WriteLine(name.Substring(0, 2));
Console.WriteLine($"{name}: {ports} Ports");

    Größe ändern?

    Ein Array behält seine Größe. Weißt du vorher nicht, wie viele Elemente kommen, nimm eine Liste.

    LISTE IN ZEITLUPEKlicke dich Zeile für Zeile durch das Programm.
    Typische Fallen: Eine Schleife mit i <= namen.Length greift am Ende auf einen Index zu, den es nicht gibt. Und name.ToUpper(); allein bringt nichts: Das Ergebnis wird weggeworfen.

    Methoden

    Methoden schreiben, aufrufen und ihren Rückgabewert verwenden.

    Dieselbe Prüfung an fünf Stellen kopiert heißt: Beim nächsten Fehler reparierst du fünfmal und vergisst eine. Eine Methode ist ein benannter Codeblock, den du beliebig oft aufrufst. Einmal reparieren, überall behoben.

    static int Addieren (int a, int b) │ │ │ └ Parameter: was hineinkommt │ │ └ Name │ └ Rückgabetyp: was herauskommt └ gehört nicht zu einem einzelnen Objekt
    void heißt: gibt nichts zurück. Jeder andere Rückgabetyp verlangt ein return mit passendem Wert. return beendet die Methode sofort.
    VORGEMACHT
    Eine Methode addiert, der Aufrufer entscheidet, was mit dem Ergebnis passiert:
    static int Addieren(int a, int b)
{
    return a + b;
}

int ergebnis = Addieren(2, 3);
Console.WriteLine(ergebnis * 10);
    1. Der Aufruf übergibt 2 und 3. In der Methode heißen sie a und b.
    2. return a + b; schickt 5 an die Aufrufstelle.
    3. Der Aufruf wird durch diese 5 ersetzt und in ergebnis gespeichert.
    4. 5 × 10 = 50 wird ausgegeben.

    void gegen return

    Eine void-Methode tut etwas, etwa eine Meldung ausgeben. Eine Methode mit Rückgabetyp liefert einen Wert, mit dem du weiterarbeitest. „Ausgeben“ und „Zurückgeben“ sind zwei verschiedene Dinge.

    static void Melde(string text)
{
    Console.WriteLine("Hinweis: " + text);
}

static bool IstGerade(int zahl)
{
    return zahl % 2 == 0;
}

Melde("Backup fertig");
Console.WriteLine(IstGerade(7));

    Gültigkeitsbereich

    Eine Variable lebt in dem Block aus { }, in dem sie angelegt wurde. Außerhalb kennt sie niemand.

    static void Test()
{
    int nurHier = 1;
}

Console.WriteLine(nurHier);

    Kopien

    Wird ein int übergeben, bekommt die Methode eine Kopie. Ändert sie den Parameter, bleibt das Original beim Aufrufer gleich.

    static void Erhoehe(int wert)
{
    wert++;
}

int zahl = 5;
Erhoehe(zahl);
Console.WriteLine(zahl);
    METHODENAUFRUF IN ZEITLUPEKlicke dich Zeile für Zeile durch das Programm.
    Typische Fallen: Eine Methode, die ihr Ergebnis nur mit WriteLine ausgibt, liefert dem Aufrufer nichts zum Weiterrechnen. Und Addieren(2, 3); ohne Zuweisung wirft das Ergebnis direkt weg.

    Objektorientierte Programmierung

    Klassen lesen und Objekte daraus verwenden.

    Ein Router hat Hersteller, IP-Adresse und Status. Dafür schreibst du eine Klasse: den Bauplan. Daraus entstehen mit new beliebig viele Objekte, auch Instanzen genannt. Der Bauplan routet noch nichts. Genau wie der Netzwerkplan an der Wand.

    Klasse Router (Bauplan) ├─ Objekt r1: Ip = "10.0.0.1", Online = true └─ Objekt r2: Ip = "10.0.0.2", Online = false
    Eine Klasse beschreibt Daten und Verhalten. new erzeugt ein Objekt. Der Konstruktor heißt wie die Klasse und läuft beim Erzeugen. Der Punkt greift auf Mitglieder des Objekts zu.
    VORGEMACHT
    Ein Router mit Eigenschaft, Konstruktor und Methode:
    Router r1 = new Router("10.0.0.1");
r1.Online = true;
Console.WriteLine(r1.Status());

class Router
{
    public string Ip { get; set; }
    public bool Online { get; set; }

    public Router(string ip)
    {
        Ip = ip;
    }

    public string Status()
    {
        return Ip + (Online ? " online" : " offline");
    }
}
    1. new Router("10.0.0.1") erzeugt ein Objekt und ruft den Konstruktor auf.
    2. Der Konstruktor speichert den Text in der Eigenschaft Ip.

    Felder, Eigenschaften und Kapselung

    Ein Feld ist eine Variable in der Klasse. Eine Eigenschaft mit get und set regelt den Zugriff von außen. public darf jeder benutzen, private nur die Klasse selbst. Kapselung heißt: Interna verstecken, damit niemand den Zähler auf −3 setzt.

    class Zaehler
{
    private int wert;
    public static int Gesamt = 0;

    public void Plus()
    {
        wert++;
        Gesamt++;
    }

    public int Wert()
    {
        return wert;
    }
}

    static gehört zur Klasse statt zu einem Objekt. Gesamt gibt es deshalb nur einmal, wert pro Objekt.

    Vererbung

    Fehler erkennen und behandeln

    Fehlerarten unterscheiden und fehlerhaften Code reparieren.

    Es gibt drei Sorten Ärger. Ein Compilerfehler verhindert den Start, dazu gehören Syntaxfehler. Ein Laufzeitfehler tritt erst beim Ausführen auf, etwa wenn jemand „abc“ eintippt und du eine Zahl erwartest. Ein logischer Fehler ist die gemeinste Sorte: Das Programm läuft fröhlich und liefert Unsinn.

    Compilerfehler → Programm startet nicht Laufzeitfehler → Programm startet, Ausnahme beim Ausführen Logischer Fehler → Programm läuft, Ergebnis falsch
    Fehlermeldung von vorn lesen: Datei, Zeile, Fehlercode, Text. Der erste Fehler zuerst, viele weitere sind oft nur Folgen davon. Ausnahmen fängst du mit try und catch.
    VORGEMACHT
    Eine Eingabe, die keine Zahl ist, ohne dass das Programm abstürzt:
    try
{
    int zahl = int.Parse("abc");
    Console.WriteLine("Zahl: " + zahl);
}
catch (FormatException)
{
    Console.WriteLine("Das war keine Zahl.");
}
finally
{
    Console.WriteLine("Fertig.");
}
    1. int.Parse("abc") löst eine FormatException aus.
    2. Der Rest des try-Blocks wird übersprungen.
    3. Der passende catch-Block läuft.
    4. finally läuft immer, ob mit oder ohne Fehler.

    Prüfen statt abstürzen

    Bei Benutzereingaben ist int.TryParse oft besser: Es liefert true oder false und legt die Zahl im out-Parameter ab. Falsche Eingaben sind schließlich kein Ausnahmefall, sondern Dienstag.

    string eingabe = "24";
if (int.TryParse(eingabe, out int ports))
{
    Console.WriteLine(ports + 1);
}
else
{
    Console.WriteLine("Bitte eine Zahl.");
}

    VORGEMACHT
    Der Kern des Menüs. Die Schleife läuft, bis jemand „0“ wählt:

    Console.WriteLine("1 = Anzeigen, 0 = Ende");

    2. Das Menü erscheint und das Programm wartet auf eine Eingabe.

    4. Bei „0“ endet die Schleife, und das Programm verabschiedet sich.

    Der komplette Gerätemanager

    Lege ein Projekt mit dotnet new console an und schreibe das in Program.cs. Starte es mit dotnet run.

    List<Geraet> geraete = new List<Geraet>();
string? wahl = "";

while (wahl != "0")
{
    Console.WriteLine("1 = Hinzufügen, 2 = Liste, 0 = Ende");
    wahl = Console.ReadLine();

    switch (wahl)
    {
        case "1":
            Hinzufuegen(geraete);
            break;
        case "2":
            Anzeigen(geraete);
            break;
        case "0":
            Console.WriteLine("Tschüss");
            break;
        default:
            Console.WriteLine("Unbekannte Auswahl");
            break;
    }
}

static void Hinzufuegen(List<Geraet> liste)
{
    Console.WriteLine("Name?");
    string? name = Console.ReadLine();
    Console.WriteLine("Typ?");
    string? typ = Console.ReadLine();

    if (string.IsNullOrWhiteSpace(name) || string.IsNullOrWhiteSpace(typ))
    {
        Console.WriteLine("Name und Typ dürfen nicht leer sein.");
        return;
    }

    liste.Add(new Geraet(name, typ));
}

static void Anzeigen(List<Geraet> liste)
{
    if (liste.Count == 0)
    {
        Console.WriteLine("Noch keine Geräte.");
    }

    foreach (Geraet g in liste)
    {
        Console.WriteLine(g.Zeile());
    }
}

class Geraet
{
    public string Name { get; }
    public string Typ { get; }

    public Geraet(string name, string typ)
    {
        Name = name;
        Typ = typ;
    }

    public string Zeile()
    {
        return $"{Name} ({Typ})";
    }
}

    using System.Linq;

int[] werte = { 1, 3, 5 };
Console.WriteLine(werte.Where(x => x > 2).Count());

    Dateiverarbeitung

    Asynchrone Programmierung

    Mit async und await wartet ein Programm etwa auf Netzwerk, ohne die Oberfläche oder einen Thread zu blockieren. Wichtig bei Servern und Apps. Für den Einstieg reicht es, den Zweck zu kennen.

    await Task.Delay(10);
