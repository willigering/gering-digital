    01

    TCP oder UDP?

    Zuverlässigen Bytestrom und einzelne Datagramme auseinanderhalten.

    Du schickst einer Kollegin eine Datei. Ein fehlendes Stück macht sie unbrauchbar. Bei einer Live-Sprachverbindung ist dagegen ein verspätetes Wort oft wertlos. Daraus ergeben sich unterschiedliche Anforderungen an den Transport.

    TCP — Transmission Control Protocol bietet einen zuverlässigen, geordneten Bytestrom. Es bestätigt empfangene Daten und sendet nicht bestätigte Bytes erneut. UDP — User Datagram Protocol sendet einzelne Nachrichten, die Datagramme. Es baut selbst keine Verbindung auf und garantiert weder Zustellung noch Reihenfolge.

    Eine Anwendung kann oberhalb von UDP eigene Zuverlässigkeit ergänzen. Ein Beispiel ist QUIC, die Transportbasis für HTTP/3. Weder TCP noch UDP verschlüsseln allein den Inhalt.

    TCP: geordnete Bytes. UDP: einzelne Datagramme. Zuverlässigkeit ist keine Verschlüsselung.
    BEISPIEL MIT LÖSUNGSWEG

    Ein Backup soll vollständig ankommen. Die Anwendung möchte Zuverlässigkeit vom Transportprotokoll. Welches passt?

    1. Die Datei braucht alle Bytes in der ursprünglichen Reihenfolge.
    2. TCP ergänzt Bestätigungen, Reihenfolge und erneutes Senden.
    3. Antwort: TCP. Ein zusätzlicher Schutz wie TLS ist für Vertraulichkeit nötig.

    Ein UDP-Header ist 8 Byte lang. Bei 120 Byte Nutzdaten ist das UDP-Datagramm 128 Byte lang. IP- und Ethernet-Header kommen außerhalb davon hinzu. TCP-Header sind mindestens 20 Byte lang; Optionen können sie vergrößern. Weniger Header bedeutet nicht automatisch eine schnellere Anwendung.

    Anforderungen vergleichenWerte ändern und Zusammenhang prüfen · ohne Wertung
    Typische Falle: UDP bedeutet nicht, dass eine darauf aufbauende Anwendung niemals zuverlässig arbeiten kann. QUIC ergänzt genau solche Funktionen. TCP allein macht Daten nicht geheim.

    02

    Ports & Verbindungen

    Standardports zuordnen und Hin- und Rückweg einer Verbindung lesen.

    Auf dem Firmenserver laufen Website und SSH gleichzeitig. Die IP-Adresse benennt den Rechner. Eine Portnummer bezeichnet einen Endpunkt des Transportprotokolls auf diesem Rechner. HTTP und SSH haben verschiedene Standardports.

    Der Client wählt gewöhnlich einen freien Quellport und sendet an den Server-Zielport. TCP und UDP besitzen getrennte Portbereiche mit je 16 Bit. Es gibt die Nummern 0 bis 65535; Port 0 ist reserviert.

    Eine TCP-Verbindung wird durch beide IP-Adressen und beide Ports unterschieden. Im Rückweg tauschen Quelle und Ziel die Rollen.
    BEISPIEL MIT LÖSUNGSWEG

    192.0.2.10:51000 sendet per TCP an 198.51.100.20:443. An welchen Port geht die Antwort?

    1. Der Client-Endpunkt ist 192.0.2.10:51000.
    2. Der Server antwortet von 198.51.100.20:443 an diesen Client-Endpunkt.
    3. Gesuchter Zielport: 51000, nicht 443.

    IANA ist die Stelle für die Portregistrierung. System Ports: 0–1023, User Ports: 1024–49151, Dynamic/Private Ports: 49152–65535. Betriebssysteme können andere Bereiche für automatisch gewählte Client-Ports konfigurieren. Ein offener Port beweist nicht, dass dort tatsächlich der übliche Dienst läuft.

    Portverzeichnis erkundenWerte ändern und Zusammenhang prüfen · ohne Wertung
    Typische Falle: Port ist keine Hardware-Buchse. Port 443 allein beweist weder HTTPS noch sichere Inhalte. TCP 53 und UDP 53 sind verschiedene Transportendpunkte.

    03

    TCP auf- und abbauen

    Handshake, Bestätigungsnummern und reguläres Verbindungsende verstehen.

    Dein Browser öffnet eine TCP-Verbindung. Zuerst vereinbaren beide Seiten ihren Start im Sequenzraum: SYN heißt Synchronisieren, ACK heißt Bestätigen. Der reguläre Aufbau lautet SYN → SYN-ACK → ACK.

    Die Sequenznummer nennt bei Daten die Position des ersten Bytes. Die Bestätigungsnummer nennt das nächste erwartete Byte. SYN und FIN belegen jeweils eine Sequenznummer, ein reines ACK keine. FIN zeigt an: Diese Seite sendet keine weiteren Daten. Beide Richtungen können getrennt geschlossen werden.

    ACK = erstes Byte nach den bestätigten Daten. SYN und FIN zählen jeweils eins.
    BEISPIEL MIT LÖSUNGSWEG

    Ein Segment startet bei Sequenznummer 1000 und enthält 200 Datenbytes, ohne SYN und FIN. Welche ACK-Nummer folgt?

    1. Das erste Datenbyte hat Nummer 1000.
    2. 200 Bytes belegen die Nummern 1000 bis 1199.
    3. Das nächste erwartete Byte ist 1200. Die Antwort bestätigt mit ACK 1200.

    Regulärer Abbau: A sendet FIN, B bestätigt mit ACK. B kann noch Daten senden und später sein eigenes FIN schicken, das A bestätigt. FIN und ACK können in einem Paket kombiniert sein; es sind daher nicht immer exakt vier Pakete. RST bricht eine Verbindung ab. Retransmission ist erneutes Senden unbestätigter Daten. Sequenznummern sind 32 Bit breit und laufen zyklisch; die Übungen vermeiden diesen Überlauf.

    ACK-RechnerWerte ändern und Zusammenhang prüfen · ohne Wertung
    Typische Falle: ACK 1200 heißt nicht „Byte 1200 ist schon angekommen“, sondern „bis 1199 bestätigt; 1200 wird erwartet“.

    04

    DHCP: Adresse gesucht

    DORA, Lease-Timer und DHCP-Vermittlung anwenden.

    Ein neuer Büro-PC weiß nach dem Start noch nicht, welche IPv4-Adresse er benutzen darf. DHCP — Dynamic Host Configuration Protocol liefert ihm eine zeitlich begrenzte Konfiguration. Diese Zuteilung heißt Lease. Dazu können Maske, Standardgateway und DNS-Server gehören.

    Bei der erstmaligen erfolgreichen Zuteilung: Discover sucht Server, Offer bietet eine Konfiguration an, Request fordert das gewählte Angebot an, ACK bestätigt es. Merkwort: DORA. DHCPv4 verwendet UDP 67 am Server und UDP 68 am Client.

    Offer ist ein Angebot. Erst ACK bestätigt die Zuteilung. Ein noch gültiges Lease verfällt nicht allein durch einen Serverausfall.
    BEISPIEL MIT LÖSUNGSWEG

    Ein Lease gilt 8 Stunden. T1 ist auf 50 % gesetzt. Wann beginnt die Erneuerung?

    1. T1 = Lease-Zeit × 0,5.
    2. 8 Stunden × 0,5 = 4 Stunden.
    3. Nach 4 Stunden fragt der Client zunächst seinen bisherigen Server. T2 wäre bei 87,5 % nach 7 Stunden.

    Die Standardwerte für T1 und T2 sind 50 % und 87,5 %. Server können andere Timer vorgeben. Bei T1 versucht der Client die Erneuerung per Unicast, bei T2 das Rebinding per Broadcast. Nach Lease-Ablauf muss er die Adresse aufgeben. Bei ausbleibender Zuteilung kann Windows APIPA — Automatic Private IP Addressing aus 169.254.0.0/16 einrichten.

    Ein Router reicht gewöhnliche Client-Broadcasts nicht einfach weiter. Ein DHCP-Relay vermittelt die Anfrage gezielt in ein anderes Netz. Der Server braucht einen passenden Adressbereich für das Client-Subnetz. DHCP ist keine sichere Geräteauthentifizierung; fremde DHCP-Server können falsche Konfiguration verteilen.

    Lease-ZeitleisteWerte ändern und Zusammenhang prüfen · ohne Wertung
    Typische Falle: 169.254.x.x ist keine erfolgreich vom DHCP-Server erhaltene Internetkonfiguration. Ein Offer allein reicht ebenfalls nicht.

    05

    DNS: Namen statt Nummern

    Record-Typen, Cache-Gültigkeit und DNS-Fehler unterscheiden.

    Du öffnest portal.example. Der Rechner braucht dazu die passende IP-Adresse. DNS — Domain Name System ist das verteilte Namenssystem. Ein Resolver fragt Informationen ab, ein autoritativer Server beantwortet die Daten seiner Zone verbindlich. Eine Zone ist ein verwalteter Teil des Namensraums.

    A ordnet IPv4 zu, AAAA IPv6. CNAME nennt einen Alias-Zielnamen. MX nennt die Mailserver einer Domain. PTR dient der Rückwärtsauflösung. NS nennt zuständige Nameserver. SOA enthält Verwaltungsdaten. TXT enthält Text, zum Beispiel für veröffentlichte Domainregeln.

    Erst entscheiden, was gesucht ist. Ein Name, eine IPv4-Adresse, ein Alias und ein Mailziel brauchen verschiedene Record-Typen.
    BEISPIEL MIT LÖSUNGSWEG

    Ein interner Name soll auf die IPv6-Adresse 2001:db8::20 zeigen. Welcher Record ist nötig?

    1. Gesucht ist die Zuordnung Name → IPv6-Adresse.
    2. A wäre für IPv4, MX für Mailserver und CNAME für einen anderen Namen.
    3. Der richtige Typ ist AAAA.

    Die TTL — Time to Live nennt bei DNS die Cache-Gültigkeit in Sekunden. Nach 120 Sekunden bleiben von TTL 300 noch 180 Sekunden. Änderungen sind deshalb nicht immer sofort überall sichtbar. Ein rekursiver Resolver fragt bei Bedarf weitere Server. Bei einer iterativen Auskunft erhält der Fragende auch Verweise, denen er selbst weiter folgen kann.

    Klassisches DNS nutzt UDP und TCP auf Port 53. Abgeschnittene UDP-Antworten können eine Wiederholung über TCP auslösen. Vollständige AXFR-Zonentransfers nutzen TCP. Verschlüsselte Varianten wie DNS over HTTPS sind davon zu unterscheiden. NXDOMAIN meldet einen nicht existierenden Namen, SERVFAIL einen Bearbeitungsfehler. Ein Timeout bedeutet, dass keine rechtzeitige Antwort kam.

    Record-WerkstattWerte ändern und Zusammenhang prüfen · ohne Wertung
    Typische Falle: „Es ist immer DNS“ ist ein Witz, keine Diagnose. Teste gezielt. Ein DNS-Fehler ist nicht automatisch ein kaputtes Kabel.

    06

    NAT & PAT: Wer war das?

    Übersetzungstabellen und Portweiterleitungen lesen.

    Zwei Firmenlaptops öffnen gleichzeitig dieselbe Website. Im Internet erscheinen beide mit der öffentlichen IPv4-Adresse des Routers. NAT — Network Address Translation übersetzt Adressen. PAT — Port Address Translation, auch NAPT, nutzt zusätzlich Portnummern zur Unterscheidung.

    Die Zuordnungstabelle verknüpft den internen mit dem öffentlichen Endpunkt. Antworten einer bestehenden Verbindung werden anhand dieser Zuordnung zurückübersetzt. Die Übungen geben die passende Zuordnung vollständig vor.

    Bei der Rückübersetzung die passende öffentliche Tabellenzeile suchen und dann den internen Endpunkt ablesen.
    BEISPIEL MIT LÖSUNGSWEG

    TCP 192.168.10.20:51000 ↔ 203.0.113.5:62000. Eine passende Antwort erreicht den öffentlichen Port 62000. An welchen internen Port geht sie?

    1. Die Antwort passt zur öffentlichen Zuordnung 203.0.113.5:62000.
    2. Die interne Seite derselben Zeile lautet 192.168.10.20:51000.
    3. Gesucht ist der interne Port: 51000.

    Statisches NAT bildet dauerhaft eine Adresse auf eine andere ab. Dynamisches NAT wählt aus einem Adresspool. Bei einer Portweiterleitung wird ein öffentliches Ziel auf einen internen Dienst abgebildet, etwa TCP :8443 → 192.168.10.50:443.

    Eine Firewall entscheidet separat, ob Verkehr erlaubt ist. NAT verschlüsselt nichts. In realen Verbindungen können Protokoll, Gegenstelle und Verbindungszustand für die Zuordnung relevant sein; die Unterrichtstabellen zeigen eine vereinfachte, ausdrücklich passende Zeile.

    PAT-Tabelle lesenWerte ändern und Zusammenhang prüfen · ohne Wertung
    Typische Falle: Der öffentliche Port ist nicht zwangsläufig der interne Port. NAT ersetzt weder TLS noch ein Firewall-Konzept.

    07

    ARP: Wer hat die MAC?

    Die richtige lokale Ziel-MAC bestimmen.

    Dein PC kennt die IPv4-Adresse des Ziels. Zum Senden auf einem Ethernet-Link braucht er aber eine MAC-Adresse, die Link-Adresse der Netzwerkschnittstelle. ARP — Address Resolution Protocol ermittelt zu einer lokalen IPv4-Adresse diese MAC.

    Der PC entscheidet zuerst anhand seiner Route, ob das Ziel direkt erreichbar ist. Im eigenen Subnetz fragt er nach der MAC des Zielhosts. Bei einem entfernten Ziel fragt er nach der MAC des nächsten Hops, häufig des Standardgateways.

    Die IP bezeichnet das endgültige Ziel. Die MAC bringt den Ethernet-Rahmen nur zum nächsten lokalen Empfänger.
    BEISPIEL MIT LÖSUNGSWEG

    192.168.10.10/24 sendet an 198.51.100.9. Nächster Hop ist 192.168.10.1. Wessen MAC wird gesucht?

    1. 198.51.100.9 liegt nicht im lokalen /24-Netz.
    2. Die Route nennt 192.168.10.1 als nächsten Hop.
    3. ARP fragt lokal nach 192.168.10.1. Das IP-Ziel bleibt ohne NAT 198.51.100.9.

    Eine gewöhnliche Anfrage geht an die Broadcast-MAC FF:FF:FF:FF:FF:FF. Das gesuchte Gerät antwortet normalerweise per Unicast an den Fragenden. Der ARP-Cache speichert Zuordnungen zeitweise. Gratuitous ARP und Proxy-ARP sind Sonderfälle, die Aufgaben ausdrücklich ausklammern.

    ARP gehört zu IPv4. IPv6 benutzt Neighbor Discovery über ICMPv6. Router erzeugen auf dem nächsten Ethernet-Link neue MAC-Adressen im Rahmen; sie übernehmen nicht den alten Rahmen unverändert.

    Nächsten Hop auswählenWerte ändern und Zusammenhang prüfen · ohne Wertung
    Typische Falle: ARP sucht keine entfernte Server-MAC quer durchs Internet. Eine ARP-Antwort ist außerdem keine kryptografisch bestätigte Identität.

    08

    ICMP: Ping ist kein Gütesiegel

    Echo, TTL und Traceroute richtig deuten.

    Die Website lädt nicht. Ein Ping kann ein erster Hinweis sein. ICMP — Internet Control Message Protocol übermittelt Kontroll- und Fehlermeldungen zu IP. Der klassische Ping sendet Echo Request; ein antwortender Host sendet Echo Reply.

    ICMP hat keine TCP- oder UDP-Portnummern. Es unterscheidet Meldungen durch Typ und Code. Ein erfolgreicher Ping prüft nicht, ob der Webdienst läuft. Eine fehlende Echo-Antwort beweist keinen Ausfall: Echo kann gefiltert werden.

    Erreichbarkeit eines Hosts und Funktion eines konkreten Dienstes sind zwei verschiedene Prüfungen.
    BEISPIEL MIT LÖSUNGSWEG

    Ein IPv4-Paket startet mit TTL 64 und passiert drei weiterleitende Router. Welchen Wert hat es dann?

    1. TTL begrenzt die Zahl der Weiterleitungen. Jeder Router vermindert um eins.
    2. 64 − 3 = 61.
    3. Nach drei Weiterleitungen bleibt TTL 61. Normale Ethernet-Switches zählen hierbei nicht als Router.

    Bei TTL-Ablauf sendet ein Router typischerweise Time Exceeded. Traceroute schickt Probes mit steigender TTL und macht so antwortende Zwischenstationen sichtbar. Je nach Tool sind die Probes UDP, ICMP oder TCP. Sternchen bedeuten fehlende Antworten, nicht automatisch einen unterbrochenen Weg.

    Destination Unreachable kann verschiedene Ursachen melden, etwa ein nicht erreichbares Ziel oder einen nicht erreichbaren UDP-Port. ICMPv6 hat zusätzlich zentrale Funktionen wie Neighbor Discovery; ICMP pauschal zu blockieren kann wichtige Netzfunktionen stören.

    TTL-Weg verfolgenWerte ändern und Zusammenhang prüfen · ohne Wertung
    Typische Falle: Ping 127.0.0.1 prüft keinen Weg zum Internet. Und die IP-Protokollnummer 1 von ICMP ist kein Zielport.

    09

    HTTP & HTTPS

    Methoden, Statuscodes, URL-Ports und TLS unterscheiden.

    Du rufst eine Seite auf. HTTP — Hypertext Transfer Protocol beschreibt Anfragen und Antworten. Die Methode sagt, was angefordert wird: GET liest eine Repräsentation, PUT erstellt oder ersetzt an der Ziel-URL, DELETE fordert Entfernen an. POST übermittelt Daten zur Verarbeitung. Die Anwendung entscheidet über Berechtigungen.

    Ein Statuscode beschreibt das Ergebnis. 200: erfolgreich, 301: dauerhaft umgeleitet, 403: Zugriff verweigert, 404: Ressource nicht gefunden, 500: interner Serverfehler. 1xx sind Zwischeninformationen, 2xx Erfolg, 3xx Umleitung, 4xx Fehler im Bereich der Anfrage und 5xx Serverfehler.

    HTTPS ist HTTP mit TLS-Schutz. Eine sichere Verbindung beweist keine ehrlichen Website-Inhalte.
    BEISPIEL MIT LÖSUNGSWEG

    https://portal.example:8443/status nennt ausdrücklich einen Port. Welcher Zielport gilt?

    1. HTTPS würde ohne zusätzliche Nummer gewöhnlich 443 verwenden.
    2. Die URL gibt jedoch ausdrücklich :8443 vor.
    3. Der Zielport ist 8443. Der Verbindungsaufbau muss weiterhin zum HTTPS-Schema passen.

    TLS — Transport Layer Security verschlüsselt und schützt die Integrität der Übertragung. Ein gültiges Zertifikat soll zur aufgerufenen Gegenstelle passen. TLS ist keine Bewertung der Seriosität des Betreibers.

    HTTP/1.1 und HTTP/2 über HTTPS nutzen TCP, standardmäßig Port 443. HTTP/3 nutzt QUIC über UDP, gewöhnlich ebenfalls Port 443. HTTP ohne TLS ist standardmäßig auf TCP 80. Diese Nummern sind Standardwerte und können in einer URL abweichend festgelegt werden.

    Statuscode-LupeWerte ändern und Zusammenhang prüfen · ohne Wertung
    Typische Falle: 404 zeigt, dass ein HTTP-Server geantwortet hat. Es heißt nicht „kein Internet“. HTTPS ist außerdem nicht auf TCP beschränkt: HTTP/3 nutzt UDP.

    Mail, Dateien & Fernzugriff

    Für Versand, Abruf, Dateiübertragung und Verwaltung den passenden Dienst wählen.

    Eine Mail wird verschickt und später gelesen. Dafür gibt es verschiedene Dienste: SMTP — Simple Mail Transfer Protocol versendet. IMAP — Internet Message Access Protocol verwaltet Postfächer auf dem Server. POP3 — Post Office Protocol Version 3 ist ein klassischer Abholdienst. Eine Abholung bedeutet nicht automatisch, dass jede Serverkopie gelöscht wird; das hängt von der Konfiguration ab.

    SMTP zwischen Servern nutzt gewöhnlich TCP 25. Ein Mailclient liefert über Submission ein: 587 mit STARTTLS oder 465 mit implizitem TLS. IMAP nutzt 143 beziehungsweise 993 mit implizitem TLS; POP3 110 beziehungsweise 995. STARTTLS startet zunächst im normalen Protokoll und schaltet nach Vereinbarung auf TLS um.

    SMTP versendet, IMAP synchronisiert. SFTP ist SSH-Dateiübertragung; FTPS ist FTP mit TLS. Ähnliche Namen, andere Verfahren.
    BEISPIEL MIT LÖSUNGSWEG

    Ein Admin will den Switch verschlüsselt per Terminal verwalten. Telnet oder SSH?

    1. Ungeschütztes Telnet auf TCP 23 überträgt die Sitzung im Klartext.
    2. SSH — Secure Shell — schützt den Fernzugriff, gewöhnlich über TCP 22.
    3. Antwort: SSH. Auch der Host-Schlüssel der Gegenstelle muss geprüft werden.

    FTP — File Transfer Protocol benutzt TCP 21 für Steuerbefehle. Für Dateien gibt es einen getrennten Datenkanal. Beim aktiven FTP eröffnet ihn der Server zum angekündigten Client-Port, klassisch von Server-Port 20. Beim passiven FTP verbindet sich der Client zum vom Server angekündigten Datenport. Firewalls brauchen deshalb mehr als eine pauschale Freigabe von Port 21.

    SFTP — SSH File Transfer Protocol läuft gewöhnlich auf TCP 22. FTPS ergänzt TLS zu FTP und behält dessen getrennte Kanäle. NTP — Network Time Protocol synchronisiert die Uhrzeit, gewöhnlich über UDP 123. DNS-MX-Records zeigen auf Mailservernamen, nicht direkt auf Postfachadressen oder Ports.

    Dienste im ArbeitsalltagWerte ändern und Zusammenhang prüfen · ohne Wertung
    Typische Falle: Ein anderer Telnet-Port verschlüsselt nichts. SFTP ist kein passives FTP. TCP 25 ist nicht die pauschale Standardantwort für jede Einlieferung durch Mailclients.
